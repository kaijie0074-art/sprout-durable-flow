# 修复设计与引用（v1.0.0）

## 0. 核心架构决策：把"执行"从会话里剥离

OpenClaw（交互层）只做它擅长的：对话入口、进度汇报、审批问答。执行层（本仓库）持有全部任务状态——**任务状态只进数据库，memory 只放对话偏好类软信息**（源文档 2.3 最后一条对位）。这个解耦同时把 OpenClaw 升级破坏集成层的爆炸半径降到最小。

## 1. 存储：一张 SQLite 撑起五类语义（store.py）

- `tasks`：状态机（pending/running/waiting_human/waiting_approval/succeeded）+ 步骤游标；
- `checkpoints`：每步确认时写入（步骤名 + 状态 + 时间戳）——**借 LangGraph checkpointer 的"快照+游标"建模**；
- `idempotency`：幂等键去重表（task, step, key）——**借 DBOS/Restate 的 invocation key 语义**；
- `audit`：审批/执行/跳过/确认全留痕——**参照 Temporal 的可观测事件历史**；
- `configs`：版本化项目配置，写入走 CAS。
- WAL 模式：任意步 SIGKILL 后已提交事务不丢——这是"崩溃后状态一致"的物理保证。

## 2. 引擎：三段式步骤 + 两个门（engine.py）

```
对每一步（从最后确认步重入）：
  human_wait 步 → 有 CONFIRM_REPLY 审计？→ 推进 : 置 waiting_human 挂起
  high 步      → 无 APPROVE 审计 → 置 waiting_approval 挂起（不得执行也不得跳过）
  前置探测     → journal.has(service, action, key)？→ SKIP（留审计）
  执行         → run_step 副作用 + mark_done + EXEC 审计
  确认         → save_checkpoint + 游标推进
```

- 故障注入点固定在**execute 后、confirm 前**（副作用已发生、检查点未写）——恢复最难的场景，前置探测在此救场：探测到副作用已存在 → SKIP → 继续推进。**这正是 Temporal "重放事件历史 ≠ 重执行副作用"语义的 SQLite 实现**。
- `waiting_human`：客户回复凭**任务 ID** 关联（confirm 命令），不依赖任何会话——**借 LittleHorse UserTask**。"等三天"期间每条命令都是独立进程，状态活在库里。
- 已完成任务 run = no-op：恢复语义的最后一环。

## 3. 幂等：双保险（services.py + store.py）

- 副作用全部走 journal（append-only）：发消息/渲染/签名/上传各带幂等键 `task:step`；
- 前置探测查 journal；idempotency 表兜底（journal 属文件、表属库，两层独立可查）；
- 对外部黑盒系统（商店后台不支持幂等键的场景）：探测退化为"先查后台是否已有该版本再决定传不传"——journal 即这个"查"的本地镜像（源文档 2.4 第一条加重因素的应对）。

## 4. 审批门：四类高危动作（engine.py + steps.py）

外发消息 / 签名 / 上传 / 付费四类（本流水线出现前三类，`pay_channel_fee` 保留风险等级定义）。执行前需 audit 存在 APPROVE 记录；执行后写 EXEC 审计；已人工完成的动作靠幂等探测 SKIP——**"高危动作不重放" = 审批门 + 幂等键的合取**。

## 5. CAS 并发控制（store.py）

configs 表 (project, version) 主键；写入要求 expected_version == 当前最新，否则 `ConfigConflict`（携带最新版本号供人工合并）。两人/两个 Agent 同时改同一项目配置：后写被拒。**借乐观并发（compare-and-swap）惯例**。

## 6. 看门狗（watchdog.py）

扫描 `running` 且 updated 超时 → 置 pending（自动重入）+ REQUEUE 审计 + 告警事件；`waiting_human` 超时 → 告警事件（供 IM 推送）。重入的安全性由幂等前置探测兜底——**Celery 的 acks_late 重投语义反面教材：没有幂等探测的重入就是重放**。

## 显式不做（边界）

- 不做补偿事务（saga 回滚）：本流水线的副作用（发消息/上传）不可逆，策略是"防重放"而非"回滚"；
- 外部副作用走真实 HTTP 适配器（`WECOM_WEBHOOK_URL`/`SIGNER_URL`/`STORE_UPLOAD_URL`，env-gated，未配置显式报错）；OpenClaw 交互层协议（触发/通知）在本仓库外；
- 不做多 worker 并发调度：单机单进程 + WAL 足够当前吞吐；supervisor 语义由看门狗 + cron 承担。
