## 关键测试技术说明

- **真实 SIGKILL**：`--crash-at STEP` 由引擎在"execute 后、confirm 前"对自身 `os.kill(pid, SIGKILL)`；测试以子进程运行 CLI，断言 returncode 非零。注入点选最毒位置：副作用已落、检查点未写——恢复只能靠前置探测。
- **等待穿透**：crash 点在 `wait_customer_confirm` 之后的步骤时，测试驱动器自动 confirm/approve 穿过挂起点再抵达注入点（`helpers.drive`）。
- **会话蒸发的物化**：每条 CLI 都是独立进程，仓库根本没有"会话"可依赖——状态全在 SQLite/journal 文件里。
- **确定性**：回归测试经 `DURABLE_FLOW_SERVICES_MODULE=local_services`（tests/ 内本地执行后端）注入，无外部依赖；产品默认真实 HTTP 适配器。`watchdog --stale -1` 使"超时"立即成立，不依赖真实时钟等待。
