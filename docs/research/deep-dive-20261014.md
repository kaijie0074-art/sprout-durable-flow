## Q1：全步骤 × 全原子边界的崩溃注入，恢复语义真的完备吗？

**假设**：引擎只在「execute 后、confirm 前」一个固定点注入 SIGKILL（8 格）；若把每步拆到
7 个原子边界（probe / inflight 落账前 / 外部效果已发-journal 确认前 / 确认后 / 幂等落库后 /
EXEC 审计后 / checkpoint 后），存在恢复语义覆盖不到的窗口。

**实验**（复现：`python3 evidence/deep-dive/run_matrix.py`）：
- 注入服务 `crashpoint_services.py` 把每个副作用拆两阶段——①写 `external_world.jsonl`
  （外部世界真相源，等价"HTTP 已达服务器"）②journal 幂等确认；对 `Store.mark_done/audit/
  save_checkpoint` 打补丁实现库内边界注入；SIGKILL 不给清理机会。
- 判定以真相源为准：PASS=恢复到 succeeded 且 7 个副作用各恰好一次；REPLAY=任一 >1；LOSS=succeeded 但 =0；STUCK=无法到终态。

**数据**（`data/q1-matrix.json`，44 格 = 7 执行步 × 6 边界 + 人工等待步 2 边界）：

| 判定 | 格数 | 位置 |
|---|---|---|
| PASS | 37 | 除 mid_exec 外全部 |
| **REPLAY** | **7** | **每个执行步的 mid_exec（效果已发生、确认未落账）** |

另发现：`post_ckpt`（checkpoint 已写、游标未推进）恢复后同一步产生**重复 checkpoint 行**。

**结论**：journal-only 幂等防不住「派发后、确认前」窗口——重放 = 客户收到两条一样的消息/
商店出现重复版本。这正是分布式系统"客户端侧恰好一次不可能"（无服务端去重的非幂等 API）
在本状态机上的具体形态；其余 5 类边界引擎设计（WAL + 前置探测 + 检查点重入）全部自愈。

## Q2：恰好一次窗口能否工程闭合？——#inflight 派发边界 WAL + 人工裁决

**假设**：把幂等确认拆成 `#inflight`（派发边界，先于外部效果落账）与确认两条记录，
恢复时「inflight 有、确认无」= 结果不确定 → 机器禁止自动重发，转人工裁决
（assume_done=核实已发生不重发 / resend=核实未送达允许重发），可把 REPLAY 压到 0。
方案取舍：标记放派发后 → 退化为 at-least-once（REPLAY）；放派发前 → at-most-once +
不确定窗口交人工——对客户外发类副作用，宁停勿重。

**实现**：
- `services.Journal.mark_inflight()`；四个真实 HTTP 适配器（WeCom/Renderer/Signer/StoreUpload）
  在外部效果前落 `#inflight`；`engine` 前置探测新增不确定分支 → `waiting_approval` + `UNCERTAIN` 审计；
- `approve --resolution assume_done|resend` 两种裁决；assume_done 落 `UNCERTAIN_RESOLVED`+幂等标记
  （跳过执行），resend 落 `UNCERTAIN_RESEND`（允许重执行一次）；
- `Store.save_checkpoint` 改为按 (task_id, step) 幂等重写，消除重复 checkpoint。

**数据**（`data/q1-matrix-after-q2.json`，51 格 = 原 44 + 新增 inflight_pre 边界 ×7）：

| 判定 | 格数 |
|---|---|
| PASS | **51/51**（0 REPLAY、0 LOSS） |

人工核实模拟（查真相源后选裁决）：`inflight_pre`/`mid_exec` 格各 +1 次人工触碰，其余与
基线一致（3 审批 + 1 客户确认）。回归：`tests/test_uncertain_outcome.py` 4 项。

**结论**：客户端侧能拿到的最强语义 = at-most-once + 不确定结果人工裁决；"是否已送达"
这一比特信息在崩溃中物理丢失，只能由人从外部系统读回——这是状态机（而非模型）层面的
原理性上限，工程上已闭合到人这一环。

## Q3：两个进程同 base-dir 同任务并发 run，会发生什么？

**假设**：前置探测是 check-then-act，无互斥则两进程可同时通过探测 → 双执行 → 副作用重复。

**实验**（复现：`python3 evidence/deep-dive/run_race.py`）：栅栏同步构造确定性
probe-probe 重叠——两进程在 gen_config 执行前等同一栅栏文件，保证都完成"探测→未见"。

**数据**（`data/q3-race.json`）：`RACE_DUPLICATED`——gen_config 副作用 **×2**，两进程均
exit 0（静默重复，无任何报错）。**修复后**（`data/q3-race-after-fix.json`）：`SERIALIZED`，
副作用各 ×1，后到进程 exit 3 + `task_busy`。

**实现**：`durable_flow/locks.py` per-task flock（POSIX）；`Engine.run` 持锁执行；
进程死亡（含 SIGKILL）内核自动释放；不同任务不互相阻塞。回归：`tests/test_concurrency.py` 4 项。

**结论**：SQLite 行级状态挡不住应用层 check-then-act 竞态；单任务单执行者互斥是
状态机并发语义的必要件，且 flock 的"随进程死亡自动释放"恰好免费提供了存活探针（→Q4）。

## Q4：看门狗对"合法长跑任务"的误报率？

**假设**：watchdog 仅凭 `updated` 时间戳判僵死；步骤耗时 > stale_seconds 的活任务会被
误 requeue，与新执行者构成 Q3 双执行者 → 副作用重复。锁感知（flock 存活探针）可消误报。

**实验**（复现：`python3 evidence/deep-dive/run_watchdog_fp.py`，配对对照）：
10 个 status=running、时间戳彻底超期的任务；live 组由活进程持锁，dead 组无锁残留；
pre-fix 仿真 = `watchdog.is_locked` 打桩恒 False（即修复前无锁感知语义）。

**数据**（`data/q4-watchdog-fp.json`）：

| 指标 | pre-fix | post-fix |
|---|---|---|
| 活任务误 requeue 率（FP） | **10/10 = 1.0** | **0/10 = 0.0**（10 条 skip_requeue_locked 事件） |
| 死任务正确 requeue 率（TP） | 10/10 | **10/10 = 1.0**（无漏报） |

**结论**：时间戳超时 ∧ 锁空闲才可重入——把"长步骤"与"执行者已死"区分开；
误报修复不以漏报为代价。回归并入 `tests/test_concurrency.py::test_watchdog_skips_live_runner`。

## Q5：真实 LLM 生成多步工作流 DSL，状态机验证的通过率？（LLM 轮）

**假设**：小模型（glm-4-flash）能产出可解析 JSON，但对"按步骤类型变化的字段联合约束"
和"多前置步骤的传递依赖闭包"遵循不佳；复杂度升高时逻辑漏洞率上升。

**实验**（复现：`GLM_API_KEY=... python3 evidence/deep-dive/run_llm_dsl.py --phase gen`）：
自然语言规格（DSL 格式 + 业务域描述，**不含机器规则码**）→ 模型输出 JSON →
`durable_flow/dsl.py` 验证（结构层 S1–S10 / 域层 D1–D7）。三档复杂度（T1=5 步 /
T2=8 步 / T3=10 步含资金与通知）× 8 样本，串行 + 节流。

**数据**（`data/q5-gen.jsonl`）：

| 档 | 可解析 | 结构合法 | 域合法 | 完全合法 |
|---|---|---|---|---|
| T1（5 步） | 8/8 | 2/8 | 8/8 | **2/8** |
| T2（8 步） | 8/8 | 0/8 | 5/8 | **0/8** |
| T3（10 步） | 8/8 | 1/8 | 4/8 | **1/8** |

错误分类（63 条）：S9 ×30——其中"human_wait 步骤仍声明 service/action" ×20（模型强行
统一每步 schema）与"副作用步缺锚点" ×10；D ×33——几乎全是**线性链偏置**：模型让每步
只依赖前一步，而域规则要求多前置（如 upload_store 需同时传递依赖构建+签名+物料，
缺失 4 次；ios_sign←android_build 缺失 4 次；pay_channel_fee 未标 high 2 次）。

**结论**：可解析率 100% ≠ 可执行率（3/24）；弱模型的"逻辑漏洞"集中在两类系统性偏差
（schema 统一偏置、线性链偏置），不是随机噪声——这使其可被针对性工程手段治理（→Q6/Q8）。

## Q6：把验证错误回喂，模型自修复能否收敛？

**实验**（复现：`--phase repair`）：对 Q5 的 22 个不合法样本，把验证器结构化错误回喂，
要求只输出修正后的完整 JSON，一轮。

**数据**（`data/q6-repair.jsonl`）：22 → 完全修复 **2（9%）**；错误数下降 8；不变或变多 14。
拆分极具信息量：**域错误 D 被 100% 修复（33→0）**，而 **S9 的 human_wait 锚点违规
20 次全部残留**——模型收到"不得声明 service/action"的明确报错后，仍保留 action 字段
（只删 service）。即：**可推理的顺序逻辑错误一喂即好；形状/字段联合偏置喂了也不改。**

## Q7：更强模型 / 同提示词重复采样，上限在哪里？

**实验**（复现：`--phase determin` / `--phase ceiling`）：
确定性——T2 提示词重复 5 次（`data/q7-determin.jsonl`）：5 次输出两两不同（unique=5），
0/5 合法；上限对照——glm-5.3-flash 对最难档 T3 重采样 8 次（`data/q7-ceiling.jsonl`）。

**数据**：5.3-flash **8/8 完全合法**（4-flash 同档 1/8）。

**结论**：同温度下弱模型输出非确定且一致地不合法（失败模式稳定、样本不稳定）；
"对状态机约束的零样本遵循"是**小模型能力边界**而非 LLM 类边界——强一个档位的
模型零样本全过。

## Q8：弱模型的系统性偏差能否被提示词工程修复？（工程 vs 模型上限的分界）

**实验**（复现：`--phase harden` / `--phase harden2`）：harden 提示 = 原规格 + 字段联合
规则显式重申 + 正反例（正例就是 S9 违规的形状）；harden2 = 在 harden 生成的不合法样本上
再做一轮 Q6 式错误回喂。

**数据**（`data/q8-harden.jsonl` / `data/q8-harden2.jsonl`）：

| 配置 | 完全合法率 |
|---|---|
| 4-flash 零样本（T2 档） | 0/8 |
| 4-flash + harden 提示 | 2/6（**S9 违规 0 残留**；残留错误全为 D 类线性链偏置） |
| 4-flash + harden + 1 轮验证回喂 | **6/6 = 100%**（2 生成即合法 + 4 修复） |

**结论**：S9（schema 统一偏置）**提示词可治**（显式反例即可）；D（传递依赖闭包）
**提示词难治**（harden 后 4/6 仍犯）但**验证回喂可治**（Q6 中 D 33→0）。
两类偏差组合治理后，弱模型也能进入 100% 合法的生成→验证闭环——
**"生成→验证→回喂"闭环是把模型缺陷挡在状态机门外的必要件，而非可选优化。**

## 瓶颈结论

1. **状态机层（物理上限）**：非幂等外部 API 上"副作用是否已送达"这一比特在崩溃中
   物理丢失——客户端恰好一次不可能（Q1：44 格矩阵 7 REPLAY）。工程闭合 = at-most-once
   + #inflight 派发边界 WAL + 人工裁决（Q2：51/51 PASS），残余代价 = 不确定窗口 +1 次
   人工触碰。证据：`data/q1-matrix.json` → `data/q1-matrix-after-q2.json`。
2. **并发层（语义上限）**：check-then-act 前置探测在无互斥时必然可重入双执行
   （Q3：gen_config 副作用 ×2 且双进程 exit 0 静默）；flock 单任务单执行者 + 看门狗锁
   存活探针后 FP 1.0→0.0 / TP 1.0 不漏（Q3/Q4）。证据：`data/q3-race*.json`、`data/q4-watchdog-fp.json`。
3. **LLM 层（小模型指令遵循上限）**：glm-4-flash 零样本生成工作流完全合法率 3/24，
   两类系统性偏差（schema 统一偏置 S9、线性链偏置 D）；错误回喂治 D 不治 S9，
   显式反例治 S9 不治 D，**组合闭环 100%**；glm-5.3-flash 同任务零样本 8/8。
   证据：`data/q5-gen.jsonl`…`data/q8-harden2.jsonl`。
   即：瓶颈不在"能否生成 JSON"，而在"无反馈时对异构字段约束与传递依赖闭包的遵循"；
   该上限随模型档位消失（5.3-flash），且在弱模型上可被验证器闭环完全补偿。

（满足停止条件：达到 8 轮；Q5–Q8 连续四轮收敛于同一类"小模型约束遵循"上限且给出了
工程可治/不可治的分界与物理层独立上限的实验证据。）
