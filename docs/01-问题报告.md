# 问题报告：长任务的状态与恢复缺失

- **编号**：对应仓库 Issue #1
- **严重度**：P0（流水线任意一步失败即人工从头排查；外发/上传重放直接损伤客户关系与商店后台）
- **影响面**：全部站点的 渲染→打包→提审 交付链；夜间/周末无人值守窗口
- **报告日期**：2026-10-13
- **状态**：已修复（v1.0.0，PR #2）

## 1. 现象

典型流水线：`生成配置 → 渲染预览 → 截图发客户 → 等客户确认（数小时~数天） → Android 打包 → iOS 打包签名 → 提审材料 → 上传商店后台`。当前由对话式 Agent（个人会话）顺序驱动：**任意一步崩溃/超时/会话过期后，任务只能从头重跑**——重试即重放全部副作用；进度只有一份非结构化 memory 文本，重启后读不懂也读不全。

根因：会话模型没有 workflow 持久化、断点恢复、幂等语义、补偿事务。拿聊天记录当数据库。

## 2. 失败场景清单（每条都真实发生过/必然发生）

| # | 场景 | 后果 | 复现测试 |
|---|---|---|---|
| S1 | 中途崩溃（iOS 打包到一半进程挂） | 重启后不知道死在哪步，从头重跑 | `test_crash_at_every_step` ×8 |
| S2 | 等待期会话蒸发（客户三天后回"可以了"） | 原会话超时，上下文丢失，只能问人 | `test_wait_state_persists` |
| S3 | 重试重放副作用 | 客户收到两条一模一样的确认消息 | 同 S1 断言（wecom 键唯一） |
| S4 | 高危动作重放（提审已人工传完又传一遍） | 商店后台重复版本，审核记录污染 | `test_manually_done_upload_not_replayed` |
| S5 | 并发覆盖（两人同时改配置） | 后写覆盖先写，无锁无告警 | `test_cas_write_and_conflict` |
| S6 | 半完成状态不可见（卡等证书两小时） | 远程团队无人发现，交付延期 | `test_requeues/alerts` |
| S7 | memory 当状态存储 | 崩溃/升级后丢失或损坏，非事务性 | 全部（基线 memory.txt 对照） |

## 3. 验收判据（源文档 2.5）

| 判据 | 实测（v1.0.0） |
|---|---|
| 任意步 `kill -9` 后重启，自动从断点恢复，副作用零重放 | ✅ 8 步逐一注入（execute 后、confirm 前最毒位置）全过；副作用键无一重复 |
| "等客户三天"：会话过期不影响续跑 | ✅ 每条命令独立进程，凭任务 ID 确认续跑；客户消息恰好一条 |
| 高危动作：已人工完成的恢复时不重放 | ✅ journal 已有上传键 → SKIP 留审计，不二次上传 |
| 高危动作：未审批不执行不跳过 | ✅ 停在 waiting_approval，放行才执行，全程审计 |
| 并发写：后写被 CAS 拒绝 | ✅ 过期版本写入失败并携带当前最新版本 |
